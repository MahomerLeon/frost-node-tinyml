# Inference firmware

Runs the TFLite int8 model on the ESP32-S3 (R2), keeps the 3 h window in a
circular buffer (R6, `circular_buffer.h`) and has a BENCHMARK mode (R7).
Usage and commands: see `firmware/README.md`.

`model_data.h` is generated by `python ml/convert_tflite.py` and is not in the
repository yet, because no model has been trained with a decided threshold.
The sketch does not compile without it.

## TensorFlow Lite Micro library

Chosen: **Chirale_TensorFLowLite 2.0.0** (Arduino Library Manager), checked
with Arduino-ESP32 core 3.3.12 on the ESP32-S3 on 2026-11-12:

- It compiles and runs on the board.
- With dense layers quantized per-channel (the default of the converter), the
  node gave outputs different from the PC (45 of 100 test vectors identical).
  `ml/convert_tflite.py` therefore disables per-channel quantization for
  dense layers; with that, 100 of 100 test vectors were identical.

Other libraries listed by the Library Manager (MicroTFLite, tflm_esp32,
TensorFlowLite_ESP32, ESP_TF) were not tested. Alternatives outside Arduino:
Espressif's `esp-tflite-micro` component with ESP-IDF, or PlatformIO. Both
mean learning a different build system and porting the sketches, so they are
only worth it if the Arduino library stops being enough.

## Pipeline test (not a project result)

Measured on the board on 2026-11-12 with a **placeholder model** (20 inputs,
16 and 8 hidden units, 2 classes, trained with a placeholder threshold only
to test the code). The numbers show that the measurement works; they must be
measured again with the real model.

| Measurement | Value |
|---|---|
| Latency, 200 runs | mean 0.050 ms, std 0.014 ms |
| Tensor arena used | 876 bytes of 16 384 reserved (5.35 %) |
| Model size | 3 152 bytes |
| Sketch size | 418 896 bytes: 31.96 % of the 1 310 720 byte program partition, 2.50 % of the 16 MB flash chip |
| Heap, peak use | 49 268 of 369 936 bytes (13.32 %) |

Still missing for R7: power consumption (INA219).
